# n8n-nodes-ldo-1c-relay

[English](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/README.md) · **Русский**

Подключите 1С к n8n через собственную очередь, опубликованный HTTP-сервис 1С или сервис MSRV. Нода позволяет искать и читать документы и элементы справочников, изменять разрешённые поля, получать PDF и автоматизировать события согласования и внешние процессы.

**Текущий выпуск: [npm 0.4.0](https://www.npmjs.com/package/n8n-nodes-ldo-1c-relay/v/0.4.0) · ядро ЛДО 6.9 · контракт обмена 1.0.** В версии 0.4.0 добавлен универсальный поиск документов и справочников по метаданным. Расширение ЛДО устанавливается отдельно: выберите поставку для вашей конфигурации 1С с совместимой версией ядра.

[Документация и каталог операций](https://ldo.msrv.tech/docs/n8n/) · [Совместимость](https://ldo.msrv.tech/docs/n8n/compatibility/) · [История обновлений](https://ldo.msrv.tech/docs/n8n/updates/) · [Получить расширение 1С](https://gitsell.ru/msrv-tech/ldo)

## Выберите подключение

| Транспорт | Когда использовать | Настройки подключения |
| --- | --- | --- |
| **Своя очередь** | База 1С не опубликована. Расширение обращается к вашему n8n исходящими запросами. | URL n8n и API key в credential очереди; одноразовый код подключения в 1С. |
| **Прямой HTTP** | HTTP-сервис расширения `ldo_n8n` опубликован и доступен из n8n. | URL сервиса, логин и пароль пользователя 1С в Direct credential. |
| **MSRV Relay** | Вы подключены к обслуживаемому сервису MSRV. | Адрес сервиса и выданные параметры авторизации для вашего подключения. |

**Своя очередь и прямой HTTP не обращаются к ресурсам MSRV и не требуют активации MSRV.** Сервисы MSRV предоставляются подключённым клиентам отдельно. Установка публичной ноды сама по себе не даёт к ним доступа.

В текущем интерфейсе ноды по умолчанию выбрана своя очередь. Существующие workflow с версией ноды 1 сохраняют транспорт Relay. См. [инструкции подключения на русском](https://ldo.msrv.tech/docs/n8n/transports/), [подробную настройку очереди и HTTP на английском](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/docs/standalone.md) и [подключение MSRV](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/docs/connection.md).

## Установка и первое подключение

1. В self-hosted n8n откройте **Settings → Community nodes → Install** и укажите `n8n-nodes-ldo-1c-relay`. Пошаговая [инструкция установки своего n8n и ноды](https://ldo.msrv.tech/articles/ustanovka-n8n-1c-self-hosted.html).
2. Установите расширение ЛДО в 1С отдельно. Выберите подходящую конфигурацию и вариант установки; ядро не является универсальным CFE для любой базы.
3. Выберите транспорт и создайте соответствующий credential:
   - **LDO 1C Standalone Queue API:** корневой URL вашего n8n и API key. Выполните **Create Connection**, затем вставьте одноразовый код в расширении: самостоятельная настройка → **Очередь**. Адрес шлюза передаётся внутри кода; API key n8n в 1С не передаётся.
   - **LDO 1C Direct API:** URL опубликованного сервиса, логин и пароль пользователя 1С. Разрешите прямой доступ в расширении; профиль доступа определяется автоматически.
   - **LDO Relay API:** адрес подключённого сервиса MSRV, ограниченный токен Relay и выданные идентификаторы базы, профиля и политики.
4. Разрешите нужные объекты и действия в 1С. Для очереди проверьте опрос по расписанию. Выполните **Get Capabilities**, затем первую разрешённую операцию.

Секретные значения вводятся в поля паролей и хранятся в зашифрованных credentials n8n. Нода не читает переменные окружения или локальные файлы.

Публикация в npm и верификация n8n — отдельные этапы. Наличие пакета в npm не означает его доступность в панели нод n8n Cloud. Демонстрация версии 0.3.0 отправлена на ручное ревью 14 октября 2026 года; [сведения о верификации](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/docs/verification.md).

## Что умеет нода

| Resource | Действия |
| --- | --- |
| **1C Operation** | Получить capabilities; найти документы и элементы справочников; прочитать и изменить их поля; найти ссылочные значения и изменить ссылочное поле; подготовить PDF документа; запустить, прочитать, перевести, изменить или отменить внешний процесс. |
| **Event** | Получить события начала согласования, согласования и отклонения документа. |
| **Delivery** | Подтвердить обработку события, назначить повтор или подтвердить доставку PDF через MSRV Relay. |
| **Connection** | Создать подключение очереди, проверить состояние, обновить код подключения, отключить связь. |
| **Queue** | Получить сохранённый результат команды и очистить старые завершённые записи. |

Ноду также можно подключить как инструмент **AI Agent**. Агент работает с теми же credentials и локальными разрешениями, без произвольного доступа к 1С.

Типы объектов, поля, печатные формы, профили процессов и переходы берутся из **capabilities** подключённой базы. Названия и бизнес-значения сохраняют исходный язык. Результат поиска можно передать следующему шагу workflow без ручного копирования UID. При неоднозначном поиске нельзя автоматически выбирать первый объект.

## Примеры workflow

- [Получить capabilities](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/examples/get-capabilities.json): Manual Trigger → Get Capabilities.
- [Создать подключение очереди](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/examples/create-queue-connection.json): создать шлюз и связать его с 1С.
- Search → Get Fields: найти документ или элемент справочника по разрешённым реквизитам, затем передать тип объекта и ID выражениями n8n.
- [Очередь с Wait](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/examples/queue-with-wait.json): отправить команду без ожидания, сохранить ожидание и получить результат позже.
- События согласования: Schedule Trigger → Event → ваша логика → Delivery: Acknowledge Event. Сохраняйте `_ldo.event_id`, а для своей очереди также `_ldo.lease_token`.
- Отправка PDF: Prepare Document PDF → нода почты или хранилища с бинарным полем `data`. Подтверждайте доставку после приёма файла получателем. Для MSRV Relay используйте Confirm PDF Delivery и сохраняйте `_ldo.event_id`, `_ldo.file_id` и `_ldo.sha256`.

## Совместимость и ограничения

- **Нода 0.4.0 совместима с ядром ЛДО 6.8 и 6.9; рекомендуется ядро 6.9.** Версия ядра — первые два компонента версии расширения. Адаптации для конфигураций 1С распространяются отдельно. См. [поддерживаемые пары](https://ldo.msrv.tech/docs/n8n/compatibility/) и [обновления компонентов](https://ldo.msrv.tech/docs/n8n/updates/).
- Требуются Node.js **22.22.0+**, контракт **1.0** и совместимый self-hosted n8n. Для своей очереди также нужны Public API/Data Tables n8n и доступность шлюза с сервера 1С. Для MSRV требуется поддержка операции подключённым сервисом.
- Опрос событий Event/Delivery использует очередь. Для прямого HTTP исходящие события могут отправляться отдельным webhook из 1С.
- Изменение объекта требует ожидаемую ревизию и локальное разрешение на запись. Изменение полей внешнего процесса не меняет исходный документ. Произвольное выполнение BSL, SQL и HTTP-запросов к базе не поддерживается.
- Создание документов и элементов справочников, проведение, отмена проведения, удаление документов и универсальное редактирование табличных частей не поддерживаются.
- Скорость очереди зависит от опроса 1С. **Minimum Wait (Seconds)** по умолчанию — 900 секунд; уменьшайте его только при соответствующем расписании опроса. Таймаут операции может достигать 1800 секунд; учитывайте лимит выполнения workflow в n8n.
- После таймаута команда может оставаться в очереди. Получите сохранённый результат или повторите запрос с **тем же Command ID и исходными параметрами**. Новый ID означает новую операцию. Доставка выполняется как минимум один раз; квитанции 1С предотвращают повторное применение той же записи.
- PDF в самостоятельном режиме ограничен **7 MiB** и занимает место в Data Tables. Настройте срок хранения очереди, данных выполнения n8n и файлов.

## Разработка и выпуск

```sh
npm ci
npm run check
npm run dev
```

Нода координирует связанные запросы: постановку команды, ожидание соответствующего результата, подтверждение и при необходимости получение и проверку PDF. Основа проекта создана официальным инструментом `n8n-node`.

`npm run check` проверяет реестр, lint, сборку и тесты с синтетическими ответами. Отдельный [серверный набор](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/test/integration/README.md) проверяет установленную ноду на временных тестовых данных. Технические отчёты и [реестр возможностей](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/docs/capabilities/README.md) сохраняют исходные версии и границы проверок.

[Порядок выпуска и верификации](https://github.com/msrv-tech/n8n-nodes-ldo-1c-relay/blob/main/docs/release.md). При изменении установки, транспорта, совместимости или операций обновляйте обе языковые версии README.
