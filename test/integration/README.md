# Воспроизводимые проверки возможностей ноды

Набор исполняет **настоящие ноды установленного пакета** в self-hosted n8n.
Подготовка и независимые проверки 1С выполняются через CodexTestBridge.
Отдельно остаются контрактные тесты `test/*.test.cjs` с синтетическими ответами.
[Матрица всех 25 действий и 6 возможностей](coverage.md) сверяется с реестром.

## Контур

```text
Python runner → n8n Public API: credentials/workflows/activation/executions
              → защищённый тестовый webhook → LDO 1C node
                                              ↓
                                      очередь или Direct HTTP
                                              ↓
                                        установленная 1С
Python runner → зарегистрированный CodexTestBridge: arrange/assert/cleanup
```

Для очереди runner вызывает штатный `ОпросКомандАвтоматизации` через bridge,
чтобы не ждать каждого периода расписания. Этот прогон подтверждает обработчик
и транспорт, но не факт автоматического запуска scheduler. Последний отдельно
подтверждён [UI-прогоном УНФ2](../../docs/capabilities/evidence/unf2-ui-2026-10-14.md).
Проверяемые операции не заменяются вызовом BSL напрямую.

## Предпосылки

- Только демобаза из реестра навыка test-databases; выбор по точному Ref.
- УНФ с совместимой обычной сборкой ЛДО, bridge и достаточными правами
  тестового пользователя. Адаптация fixtures для другой конфигурации — отдельная работа.
- Отдельный self-hosted n8n с установленным пакетом и Data Tables/Public API.
- API key с правами создания/чтения/активации/удаления собственных workflows,
  создания/удаления credentials, чтения executions и работы с Data Tables.
- Для Direct — опубликованный `ldo_n8n`, достижимый из контейнера n8n.
  Адрес проверяется по WebUrl выбранной записи реестра, другой базе он не передаётся.
- Для AI — необязательный локальный Ollama с уже установленной моделью;
  адрес должен быть достижим именно из n8n. Платный провайдер не используется.
- Для PDF — в демобазе должен быть заполненный счёт с организацией и товарами.
  Исходный счёт только читается; печатается отдельная копия.

Тест временно меняет общие настройки автоматизации и маршрут счёта; запускать
эксклюзивно в выделенной демобазе. Не использовать вместе с пользовательской
работой или другим изменяющим прогоном. Runner не включает скопированные
регламентные задания и не выдаёт доступ к MSRV.

## Запуск

Скопировать `config.example.json` в приватный `*.local.json`, указать Ref и
адреса. Секрет передаётся через переменную окружения, названную n8nApiKeyEnv.
Не вставлять API key в аргументы CLI, workflow exports или Git.
В `nodePackageVersion` указать версию фактически установленного пакета;
runner не устанавливает и не обновляет npm/CFE. Полный прогон новых исправлений
требует рабочую ноду 0.4.0 и УНФ 6.8.1.0; эти исправления пока не опубликованы.

```bash
python3 test/integration/run.py \
  --config /private/capabilities.local.json \
  --output /private/capabilities-run \
  --preflight

python3 test/integration/run.py \
  --config /private/capabilities.local.json \
  --output /private/capabilities-run \
  --allow-writes
```

Preflight только читает bridge/API и предпосылки фиксации циклов.
URL healthz после restart может отвечать раньше Public API: preflight кратко
повторяет 404/503 API, но не считает healthz доказательством готовности API.
Для запуска отдельных сценариев добавить
`--only event-document-ack,receipts,cleanup`. Неизвестный ID отклоняется.
Режимы задаются в `modes`: `queue`, `direct` либо оба, в указанной последовательности.

Необязательная настройка модели:

```json
{
  "ollama": {"url": "http://ollama-demo.example.invalid:11434", "model": "qwen3:0.6b"}
}
```

Модель не скачивается и контейнеры не запускаются самим тестом. Их подготовка
относится к инфраструктуре стенда. Для повторного запуска нужен новый output.

## Сценарии

| ID | Что проверяет |
| --- | --- |
| prepare-and-pair | Новая таблица/gateway через Create Connection; штатное сопряжение 1С; установленное расширение |
| ordinary-event-onboarding | Подписка после сопряжения включает источник событий и имеет epoch; тест не включает фиксацию скрыто вместо продукта |
| document-search / catalog-search | Поиск → чтение по полученному ID; фильтры номера/даты/организации, имени/ИНН, пагинация, Return All, пустая выдача, неоднозначность и отказы |
| search-native-policy | Прямой вызов обработчика минуя SDK: произвольный ID фильтра и отсутствие search-grant отклоняются |
| capabilities | Каталог собственных типов и процесса |
| document-read | Номер/дата/ID/revision совпадают с независимым чтением 1С |
| document-write | Комментарий и новая revision; документ остаётся непроведённым |
| catalog-read / catalog-write | Реальный элемент справочника, разрешённый реквизит, версия и проверка значения в 1С |
| reference-search | Единственное собственное значение по маркеру |
| reference-write-three-modes | ID, live и cache; фактическая ссылка документа проверяется через bridge |
| process-lifecycle | start/get/fields.update/transition/cancel; запись процесса не меняет документ |
| event-document-ack | Настоящее событие → выражение payload.object.id → чтение → ack; retry, новая аренда и отсутствие повторной выдачи |
| pdf | Native PDF, хэш/размер и binary output фактического execution |
| wait-result | Неблокирующая команда, штатная Wait и Get Result |
| receipts | Queue: точный повтор записи, stale revision, сохранённый код отказа и коллизия Command ID. Direct: stale revision, корреляция отказа и неизменность объекта |
| cleanup | Настоящий filtered delete endpoint; свежие записи сохраняются. Удаление истёкших строк отдельно проверяют контрактные тесты |
| connection-lifecycle | create/status/renew/disconnect; gateway действительно деактивируется |
| access-isolation | MSRV выключен; запрещённое поле не выдаёт данные |
| ai-tool | Реальный AI Agent вызывает ноду как инструмент; intermediate steps и ответ содержат данные native документа |

## Результаты и честные границы

- `report.json` содержит статусы сценариев и обратное отображение на все
  постоянные ID реестра; `junit.xml` подходит для CI.
- passed означает выполнение всех assertions сценария, не всех мыслимых
  вариантов конкретной операции.
- not-applicable — действие неприменимо выбранному транспорту.
- not-run — сценарий не выполнен; это не PASS.
- Failed onboarding не маскируется включением фиксации через bridge.
- AI без модели явно не проверен; один usableAsTool=true не является live-тестом.
- Confirm PDF Delivery относится только к MSRV. Для нового server E2E нужен
  изолированный enrollment именно выбранной демобазы. Этот standalone runner
  его не создаёт; действие покрыто существующим `test/nodes.test.cjs`, а новый
  реальный MSRV-прогон явно отмечается not-run. Исторические Relay-проверки
  хранятся отдельно в реестре.
- Конкурирующие аренды, протокольная авторизация и повторы дополнительно
  проверяются контрактными тестами; server suite не объявляет их доказанными
  реальной сетью только на основании mock.
- Новый прогон не является проверкой n8n Cloud, Fresh-аудитом или выпуском npm.

## CI без тестовой базы

`npm run check` включает `test:integration:check`: сверку матрицы с реестром,
регрессии редактирования секретов/ledger/повторной очистки и компиляцию Python.
Секреты и локальный реестр в GitHub CI не требуются. Live runner запускается
отдельно в контуре с зарегистрированной выделенной базой и API key; его JUnit
можно подключить к серверному CI. Наличие XML/CFE или успешного compile
не заменяет установленное расширение и реальную ноду.

Обновление матрицы после добавления сценария:

```bash
python3 test/integration/coverage.py
python3 test/integration/coverage.py --check
```

## Очистка и восстановление

Каждый запуск создаёт свои документы, сотрудника, роль, процесс, профиль,
credentials, таблицу и workflows. Приватный ledger сохраняется атомарно после
создания ресурсов. Backup настроек и маршрута не попадает в публичный отчёт.
Cleanup удаляет записи только по ID своих объектов/команд, восстанавливает
настройки и маршрут и проверяет их точное совпадение. Собираются фактические
Command ID Direct и AI observation, строки только собственной queue table
с cursor-пагинацией и квитанция live-поиска собственного уникального сотрудника.
Если восстановление 1С не удалось,
ресурсы n8n сохраняются для продолжения восстановления.

После сбоя:

```bash
python3 test/integration/run.py \
  --config /private/capabilities.local.json \
  --output /private/capabilities-run \
  --allow-writes --cleanup
```

Повторная очистка принимает уже удалённые ресурсы n8n как завершённые.
После подтверждённого восстановления 1С она не применяет старый backup снова.
Локальный file lock исключает параллельный запуск на этой базе с одного хоста;
эксклюзивность между несколькими хостами обеспечивает владелец стенда.
Не удалять `state.private.json` до successful cleanup. В нём есть конфигурация
и секреты стенда; каталог приватный, файлы имеют права 0600 и исключаются из Git.

## Проверка пары нода/ядро в разных адаптациях

`compatibility.py` использует тот же n8n Public API, gateway и приватный ledger,
но имена документа и справочника получает из тестовой конфигурации.
Production-код не подменяется и не копируется. Сценарий проверяет оба транспорта:
подключение по коду, capabilities, поиск → чтение, изменение разрешённого поля
с независимой проверкой в 1С и отказ по неразрешённому фильтру.

Скопируйте `compatibility.config.example.json` в приватное место, выберите базу
из реестра и подходящие тестовые типы её метаданных. Документ должен иметь строковый
номер и `Комментарий`; справочник — `Наименование`. Поисковые фильтры строятся с учётом его метаданных. Fixture создаёт только
собственные объекты и временный профиль. Она использует отдельный UUID базы,
отключает MSRV на время standalone-прогона и восстанавливает прежние настройки.

```bash
python3 test/integration/compatibility.py \
  --config /private/compatibility.local.json \
  --output /private/compatibility-run --allow-writes
```

Для восстановления используйте ту же команду с `--cleanup`. Не удаляйте ledger
до подтверждённой очистки. Этот короткий прогон совместимости дополняет полную
матрицу возможностей и проверки адаптации; он не заменяет PDF/AI/согласование.
