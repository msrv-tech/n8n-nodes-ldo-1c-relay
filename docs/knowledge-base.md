# Ведение реестра и публичная база знаний ЛДО

Реестр находится в публичном репозитории ноды. Он служит общей основой для
справки по операциям, руководств и [базы знаний на ldo.msrv.tech](https://ldo.msrv.tech/docs/n8n/).
Обновление от 14 октября 2026. Нода 0.4.0 соответствует ядру ЛДО 6.8. Статус публикации подтверждается npm; на сайте доступны только опубликованные релизы.

## Источники

| Материал | Роль |
| --- | --- |
| [capabilities/registry.json](capabilities/registry.json) | Редактируемый источник: назначение, результат, ограничения, транспорты, доказательства и пробелы |
| `nodes/Ldo1cRelay/Ldo1cRelay.node.ts` | Фактические имена действий и параметры интерфейса |
| [capabilities/catalog.json](capabilities/catalog.json) | Производный полный JSON для импорта в сайт/поиск; включает параметры из TypeScript |
| [capabilities/README.md](capabilities/README.md) | Производная читаемая справка с постоянными якорями |
| [Standalone](standalone.md), [MSRV](connection.md) | Инструкции подключения; ссылаются на реестр, а не ведут ещё один подробный список операций |
| Контракт в репозитории ЛДО | Схемы обмена для разработчиков; транспортные документы не подменяют справку пользователя |
| [Server suite](../test/integration/README.md) и [матрица](../test/integration/coverage.md) | Воспроизводимые сценарии с постоянными ID, JSON/JUnit и восстановлением fixtures |
| Отчёты проверок | Доказательства конкретных сценариев и сочетаний версий |

Генератор не исполняет ноду: он читает её TypeScript AST. Исходный JSON хранит
редакционные сведения, а список действий и параметры сверяются с кодом.

## Как обновлять

1. Для нового действия или изменения поведения обновить код и карточку в
   `registry.json`. Не добавлять отсутствующую операцию в implemented.
2. Сохранять постоянный `id`; переименование заголовка не меняет адрес карточки.
3. Указать доступные транспорты, ограничения локальной политики, результат,
   причины отказа и пример workflow.
4. Добавить отдельное доказательство только после фактической проверки:
   дата, версии npm/n8n/расширения/конфигурации, метод, покрытие и ограничения.
5. Добавить или обновить привязку к server/contract-сценарию; выполнить
   `python3 test/integration/coverage.py`, затем `npm run docs:build` и `npm run check`.
6. Проверить локальные ссылки и отсутствие секретов. Сгенерированные файлы
   коммитировать вместе с источником. Общий `npm run check` включает docs:check.

При смене npm-версии обновить packageVersion. Не переносить автоматически
успешный тест старого релиза в новый: существующая запись остаётся историческим
доказательством. Само отсутствие записи о реальном тесте не доказывает,
что операция сломана или не тестировалась где-либо ещё.

Статусы:

- `implemented` — возможность есть в коде; доступность требует разрешений базы.
- `not-implemented` — соответствующего действия нет.
- `needs-validation` — требуется проверка заявленного сценария/сочетания.
- `validated` — конкретный ранее непроверенный сценарий подтверждён указанным прогоном.
- `real-server` — нода исполнила реальный workflow; bridge независимо проверил 1С.
- `real-ui` — фактический UI-прогон, описанный в публичной сводке.
- `reported-real` — реальный прогон по существующему отчёту с указанными версиями.

Автоматические тесты с синтетическими ответами учитываются отдельно от
реальной 1С. Планируемые функции не превращаются в обещание сроков.

## Структура базы знаний

Рекомендуемое дерево, независимо от выбора движка сайта:

1. **Начало работы**: что установить, где получить совместимое расширение,
   что требуется в 1С и как выбрать MSRV или самостоятельную настройку.
2. **Подключение**: MSRV, своя очередь, прямой HTTP; отдельные инструкции.
3. **Операции**: одна страница на постоянный ID карточки из реестра.
4. **Сценарии**: событие → документ, чтение → запись, PDF → доставка,
   внешний процесс, ожидание результата. У каждого примера есть версии
   и статус фактической проверки.
5. **Диагностика**: pending, не запускается опрос, публикация недоступна,
   конфликт revision, смена policy, истечение результата, повтор события.
6. **Совместимость и ограничения**: проверенные сочетания, Fresh/обычная
   сборка, n8n Cloud, неподдерживаемые операции.
7. **История выпусков и проверок**: датированные результаты без выдачи
   исторических ограничений за текущее состояние.

Сайт сможет импортировать `catalog.json` из закреплённого Git commit,
построить страницы и фильтры по транспорту/группе/статусу. Английские
названия элементов интерфейса сохраняются рядом с русским объяснением.
Поиск должен учитывать оба названия, техническое имя операции и типичные
пользовательские запросы. Якорь/slug строится из `id`, а не заголовка.

Для страницы операции выводить prerequisites, параметры, результат,
workflow, ошибки, версии и доказательства. Разделять «доступно в коде»,
«разрешено вашей базой» и «проверено на таком сочетании версий».
У каждой страницы указывать дату обновления и ссылку на источник.

База опубликована 14 октября 2026 разделом документации существующего сайта:
[каталог операций](https://ldo.msrv.tech/docs/n8n/),
[машиночитаемый JSON](https://ldo.msrv.tech/docs/n8n/catalog.json),
[указатель для агентов](https://ldo.msrv.tech/docs/n8n/llms.txt).
41 HTML-страница, Markdown-копии и полный текст генерируются из явного снимка
реестра. Manifest содержит версии, хеш и сведения об исходном рабочем дереве.
Код генератора и порядок публикации находятся в основном репозитории ЛДО:
[runbook](https://github.com/msrv-tech/ldo/blob/main/docs/node-knowledge-publication.md).
Публичная справка импортируется из выпущенного npm-пакета; рабочее дерево и будущие операции в неё не попадают. Версия ядра учитывается отдельно от адаптации под конфигурацию.

## Граница публичных материалов

В реестр входят обезличенные сводки тестов и воспроизводимые схемы сценариев.
API keys, pairing codes, пароли, внутренние адреса и приватные логи остаются
вне репозиториев и сайта. Данные примеров должны быть вымышленными.

Документы архитектуры и исторические отчёты могут описывать старые версии.
Для текущих возможностей входная точка — этот реестр. Схемы контрактов
изменяются вместе с реализацией, а не автоматически из справочного текста.
