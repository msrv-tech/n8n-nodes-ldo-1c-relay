## Метод

[Runner](../../../test/integration/README.md) создаёт через n8n Public API
свои credentials, таблицы и активные workflow с защищённым webhook.
В workflow исполняется установленная LDO-нода, её выражения и штатная Wait;
операции не подменяются прямым BSL-обработчиком. Bridge создаёт fixtures,
выполняет штатный опрос очереди и независимо проверяет записанные значения 1С.

Настройки автоматизации и глобальный маршрут счёта сохраняются до изменений.
Используются новые документы, сотрудник, роль и процесс с уникальным маркером.
Для PDF создаётся отдельная копия заполненного счёта; исходник не изменяется.
Cleanup восстанавливает точные настройки/маршрут и удаляет свои объекты,
известные квитанции команд и собственные ресурсы n8n. Приватные backups,
API key, адреса и UUID бизнес-объектов не включаются в публичный отчёт.

## Событие без ручного UID

Первое сопряжение native-методом включило capture и epoch. Дополнительное
включение capture через bridge после pairing не выполнялось. Штатный метод
согласования собственного счёта сформировал `approval.started`.

Workflow: **Events → Read from event → Acknowledge**.
В параметрах Read from event заданы только выражения:

```javascript
// Document Type
={{$json.payload.object.type}}
// Document ID
={{$json.payload.object.id}}
```

Acknowledgement использует `_ldo.event_id` и `_ldo.lease_token` из Events.
Отдельно проверены retry, новая аренда, успешный ack и ноль items после ack.
Ни один UUID документа вручную в бизнес-ноду этого workflow не вводится.

## Найденные дефекты и исправления

1. Queue cleanup использовал неверный путь DELETE `/rows`: исправлен на
   официальный filtered endpoint `/rows/delete`.
2. Подключённая подписка не включала источник native событий: УНФ теперь
   сохраняет capture/epoch при явном включении подписки, без сброса действующего epoch.
3. Бизнес-отказ записи отменял вложенную транзакцию и мешал сохранить failure
   receipt: УНФ сохраняет нормализованный отказ после rollback с повторной блокировкой.
   Успешная запись и её квитанция остаются атомарными.
4. Direct получал HTTP 403 и терял нормализованный отказ: нода теперь разбирает
   только коррелированный результат контракта и сохраняет error_code/command_id
   при Continue On Fail. Несогласованные proxy/auth ответы не считаются успехом.

Регрессии закреплены тестами; обычный check ноды и 35 тестов УНФ прошли.

## Границы доказательства

- Bridge ускоряет штатный polling; этот прогон не доказывает scheduler.
- Проверен один маршрут approval.started; approval.rejected, конкурентные
  действия, restart и все возможные локальные политики не заявлены повторно проверенными.
- Cleanup через API сохраняет свежие строки; удаление старых строк проверяется
  контрактно, возраст createdAt не подменяется прямым редактированием БД n8n.
- Метаданные PDF и binary output проверены в actual execution; отказ при
  повреждённых байтах дополнительно проверяет контрактный тест.
- UI выбора динамических параметров, загрузка расширения с сайта, n8n Cloud,
  Fresh и другие конфигурации не подтверждены этим server PASS.
- Проект [поиска документов](../../design/document-search.md) остаётся проектом.
- Приватный ledger/логи предназначены для локального восстановления, не для сайта.
