# UI-проверка самостоятельной очереди на новой УНФ2

Дата: 14 октября 2026. Результат: **PASS** для перечисленных сценариев.

## Сочетание версий

- npm `n8n-nodes-ldo-1c-relay@0.3.0`.
- Отдельный self-hosted n8n `2.36.9` с новой Data Table и новым gateway.
- Конфигурация УНФ `3.0.14.168`.
- Обычная сборка расширения ЛДО `6.7.1.2`.

## Метод проверки

Подключение, настройка разрешений, создание тестового счёта, запуск чтения и
записи, а также проверка значений выполнялись через интерфейс n8n и веб-клиент
1С. Bridge, прямые HTTP-запросы к бизнес-API и выполнение BSL для проверки
результата не использовались. Подготовка инфраструктуры отдельно включала
запуск нового контейнера, сборку/установку CFE через Designer и разрешение
регламентных заданий только тестовой базы на сервере 1С.

## Подтверждённые результаты

1. Пакет установлен через Community Nodes в новом n8n.
2. Standalone Queue credential прошёл штатный тест подключения.
3. Create Connection создал gateway; код принят в интерфейсе 1С.
4. Разрешены чтение `number`/`date` и запись одного поля «Комментарий».
5. Регламентный опрос автоматически обработал Get Document Fields:
   получены номер, дата и revision тестового непроведённого счёта.
6. Update Document Fields передал ожидаемую revision и ID разрешённого поля;
   результат содержит старое/новое значение и новую revision.
7. После команды «Перечитать» интерфейс 1С показал новый комментарий.
   Документ остался непроведённым.

## Выявленная проблема среды

Первоначально копия содержала Fresh-сборку без native scheduled job;
сохранённая команда оставалась pending. После установки обычной сборки
также обнаружен серверный `scheduled-jobs-deny=on` и блокировка внешних
ресурсов копии. Они сняты только для демо-УНФ2. Опрос ЛДО включён с интервалом
30 секунд; остальные 133 скопированных задания оставлены отключёнными.
После этого новые чтение и запись прошли по расписанию, без ручного запуска.

## Границы доказательства

- Ручное указание UUID использовалось для выбора конкретного тестового счёта.
  Пользовательский путь получения ID из события здесь не проверен.
- Get Capabilities своей очереди показывает снимок политики; сам по себе
  не подтверждает исполнение команды в 1С.
- PDF, справочники, внешние процессы, события, конкурирующие записи и
  восстановление после restart в этом прогоне не проверялись.
- Это проверка самостоятельного транспорта, без настройки сервисов MSRV.
  Она не является аудитом всего сетевого трафика.
- Результат не подтверждает n8n Cloud, Fresh-аудит или другие конфигурации.

внутренней сети и пользовательских данных.
